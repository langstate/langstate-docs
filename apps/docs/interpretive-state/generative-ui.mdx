---
title: "Supporting Generative UI"
description: "Enable interactive UI components beyond plain text conversation"
---

Text-only conversation is not always the most effective interaction mode. In many applications, **interactive UI components**—such as dropdowns, multi-select lists, and form elements—significantly improve readability, efficiency, and correctness.

Interpretive State explicitly supports this by allowing **UI-oriented fields and properties** that do not belong in Canonical State.

## The Problem with Text-Only Interaction

Consider a scenario where users need to select an event:

```
System: "Please type the event name."
User: "Summer party"
System: "Event not found. Available events are: Summer Kickoff Party, 
        Summer Team Retreat, Mid-Summer Review. Please try again."
```

This back-and-forth is inefficient and error-prone.

## UI-Oriented Interpretive State

Instead of forcing text input, Interpretive State can hold UI-specific metadata:

```json
{
  "event_candidates": ["Event A", "Event B", "Event C"],
  "selection_mode": "single-select",
  "validation_rule": "required",
  "display_format": "card"
}
```

This allows the Presenter to render appropriate UI components:

<CardGroup cols={3}>
  <Card title="Dropdown List" icon="list">
    For simple selections with many options
  </Card>
  <Card title="Selectable Cards" icon="square-check">
    For rich previews with metadata
  </Card>
  <Card title="Multi-Select" icon="list-check">
    For choosing multiple items
  </Card>
</CardGroup>

## Separation of Concerns

| Layer | Contains | Example |
|-------|----------|---------|
| **Interpretive State** | UI metadata, candidates, display hints | `event_candidates`, `selection_mode` |
| **Canonical State** | Final validated value | `selected_event_id: "evt_123"` |

The UI is generated directly from Interpretive State, while Canonical State only receives the final selected event.

## Benefits

<AccordionGroup>
  <Accordion title="Better User Experience">
    Users can see available options and make informed choices without guessing.
  </Accordion>
  <Accordion title="Reduced Errors">
    Selection from predefined options eliminates typos and invalid inputs.
  </Accordion>
  <Accordion title="Clean Business Logic">
    Canonical State remains free of UI concerns, containing only validated business data.
  </Accordion>
  <Accordion title="Flexible Presentation">
    The same Interpretive State can be rendered as dropdown, cards, or voice options depending on the channel.
  </Accordion>
</AccordionGroup>

By allowing Interpretive State to carry UI-oriented properties, systems can deliver rich, interactive experiences while keeping the Canonical State minimal and authoritative.

---
title: "Evaluator"
description: "Field-by-field mutator evaluation for interpretive state transitions"
---

The evaluator module measures how well a mutator transforms a given pre-state into an expected post-state.

It runs the mutator against structured input, captures the actual post-state, and compares that result against an expected state field by field.

## Evaluation flow

```text
EvaluationContext
  ├── mutator
  ├── pre_state
  ├── expected_post_state
  ├── mutation_input
  └── metadata?

LLMEvaluator.evaluate(context)
  ├── copies the pre-state
  ├── builds MutationContext
  ├── runs mutator.mutate(...)
  ├── compares expected vs actual state
  └── returns EvaluationResult
```

## Key classes

| Class | Role |
| --- | --- |
| `BaseEvaluator` | Abstract base class for evaluator implementations |
| `Evaluator` | Shared comparison logic for state diffing |
| `LLMEvaluator` | Concrete evaluator that runs a mutator and computes results |
| `EvaluationContext` | Input bundle for a single evaluation run |
| `EvaluationResult` | Final result including score, comparison, and actual post-state |

## What gets compared

For each field path across the union of expected and actual state, the evaluator classifies the result as one of:

- `matching`
- `mismatched`
- `missing`
- `extra`

The resulting `StateComparison` is considered an overall match only when there are no mismatched, missing, or extra fields.

## Accuracy score

The evaluator computes:

```text
matching_fields / (matching_fields + mismatched_fields + missing_fields)
```

Extra fields do not reduce the score. If there are no expected fields at all, the score is `0.0`.

## Execution steps

<Steps>
  <Step title="Copy the pre-state">
    `LLMEvaluator` clones the provided pre-state so the original test fixture is not mutated.
  </Step>
  <Step title="Build mutation context">
    The evaluator wraps the copied state, structured input, and optional metadata in a `MutationContext`.
  </Step>
  <Step title="Run the mutator">
    It calls the mutator and measures wall-clock time for the operation.
  </Step>
  <Step title="Compare expected and actual">
    Shared comparison logic produces a `StateComparison` with per-field details.
  </Step>
  <Step title="Return result">
    The evaluator returns the actual post-state, comparison report, elapsed time, and accuracy score.
  </Step>
</Steps>

## Result models

### `EvaluationContext`

| Field | Description |
| --- | --- |
| `mutator` | Mutator under test |
| `pre_state` | Interpretive state before mutation |
| `expected_post_state` | Expected interpretive state after mutation |
| `mutation_input` | Structured input passed into the mutator |
| `metadata` | Optional extra metadata |

### `FieldComparison`

| Field | Description |
| --- | --- |
| `field_path` | Dot-separated field path |
| `matches` | Whether expected and actual values match |
| `expected_value` | Best expected value for the field |
| `actual_value` | Best actual value for the field |
| `difference` | Human-readable mismatch description |

### `EvaluationResult`

| Field | Description |
| --- | --- |
| `comparison` | Aggregated `StateComparison` |
| `actual_post_state` | Actual post-state from the mutator |
| `accuracy_score` | Accuracy score between `0.0` and `1.0` |
| `time_used` | Wall-clock time used by mutation |
| `metadata` | Optional metadata |

## Usage example

```python
from langstate.core import EvaluationContext, LLMEvaluator
from langstate.core.mutator.llm.schema import StructuredInput

evaluator = LLMEvaluator()

result = await evaluator.evaluate(
    EvaluationContext(
        mutator=my_mutator,
        pre_state=pre_state,
        expected_post_state=expected_state,
        mutation_input=StructuredInput(prompt="my name is John"),
    )
)

print(result.accuracy_score)
print(result.comparison.overall_match)
print(result.time_used)
```

<Note>
  The evaluator is most useful when mutator behavior is evolving quickly and you need a repeatable way to compare expected and actual interpretive state transitions.
</Note>
